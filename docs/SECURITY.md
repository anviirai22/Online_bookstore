# Security

## Controls

- Passwords are bcrypt hashes with a per-password salt and cost factor 12. Plaintext passwords are never persisted or returned.
- JWTs are signed with `JWT_SECRET`, stored in an HTTP-only cookie by default, and checked against the user's current token version and account status on every protected request.
- Logout increments the token version. Deactivating an account also invalidates its active tokens.
- Administrator routes use server-side `requireRole('admin')`; hiding a link in React is not the authorization boundary.
- Order, cart, wishlist, and review routes scope queries to the authenticated owner. Admin routes use a separate role gate.
- Zod validates account, search-related route inputs, cart quantities, address data, reviews, catalogue data, order statuses, and user status updates.
- Mongoose schemas enforce unique email/category slug, unique customer/book review, bounded quantities, and valid workflow fields.
- Prices, totals, stock, role, order status, and payment status are recomputed or verified on the server.
- Helmet, CORS allowlisting, JSON size limits, request IDs, and an API rate limiter are enabled.
- Audit events and structured security logs record authentication, admin changes, order cancellation, payment outcomes, and moderation without password, token, cookie, or card values.

## HTTPS

Local development uses HTTP on `localhost`. Deployed environments must terminate HTTPS at a reverse proxy or hosting platform, forward only HTTPS to users, set `COOKIE_SECURE=true`, and configure `CLIENT_ORIGIN` to the HTTPS origin. A representative proxy should redirect port 80 to 443 and set `Strict-Transport-Security` after HTTPS is verified.

The repository does not claim that HTTPS is active in this unconfigured local environment. `TC-SEC-04` requires a deployment-level check.

## Payment data

The application never accepts card numbers, CVV, or banking credentials. The sandbox receives only an amount and an idempotency key. Payment attempts keep a safe adapter reference and state.

## Logging and privacy

The logger recursively redacts known secret keys. Do not add request bodies, cookies, authorization headers, or payment provider payloads to logs. Production deployments should send logs to a protected sink with retention controls and should restrict MongoDB network access and backups.

## Residual risks

- A standalone MongoDB instance does not provide high availability or full multi-document transaction guarantees. Use a replica set and transaction-backed checkout for a stronger production deployment.
- The local sandbox does not test provider-specific signature validation, bank settlement, refunds, or webhook reconciliation.
- Dependency updates must be reviewed with `npm audit` and the lockfile regenerated by the project maintainer.
